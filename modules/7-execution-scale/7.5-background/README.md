# 7.5 · Фонове виконання - demo (матриця рівнів + рецепти)

Demo-проект для лекції **7.5 Фонове виконання і розклад**
(Module 7 · Execution & Scale).

На відміну від 7.2/7.3/7.7 тут немає задачі «з червоного в зелене». Лекція 7.5
про те, **де** і **коли** крутиться агент, а не про конкретну фічу. Тому головні
артефакти цього пакета - **матриця трьох рівнів розкладу** і набір **рецептів**
(`recipes/`, `routines/`). Код (`src/snippets/`) уже працює і слугує лише
зеленою ціллю, яку `/loop`-рецепт опитує.

## Що показує

- **Три рівні розкладу**, що відрізняються двома речами: що має бути ввімкнено і
  чи бачать вони локальні файли.
  - `/loop` - локально, **всередині відкритої сесії** (помирає на новій розмові;
    бачить локальні файли; найменший інтервал - 1 хвилина).
  - **desktop scheduled task** - локально, **без відкритої сесії** (машина
    ввімкнена; щоразу свіжа сесія; переживає перезапуск).
  - **cloud routine** через `/schedule` - **на інфраструктурі Anthropic** (твоя
    машина може бути вимкнена; найменший інтервал - 1 година), АЛЕ **не бачить
    локальних файлів** (щоразу свіжа копія з git).
- **Головна пастка:** хмарна рутина не бачить локальних файлів - усе під
  `.gitignore`, незакомічене чи поза git для неї не існує.
- `/background` (`/bg`) відчіплює **цілу сесію** - проти `Ctrl+B`, що ховає у фон
  лише поточну роботу всередині живої сесії.
- Дашборд `claude agents`: шість станів + групи Pinned / Ready for review;
  клавіші `Ctrl+T` (закріпити), `Space` (перегляд), `Ctrl+X` (прибрати завершені).
- Вбудовані запобіжники: термін життя 7 днів, максимум 50 задач на сесію, jitter,
  `CLAUDE_CODE_DISABLE_CRON`. Тверда стеля витрат - на тобі.

## Матриця трьох рівнів розкладу

| Рівень | Де крутиться | Бачить локальні файли? | Що має бути ввімкнено | Найменший інтервал |
|---|---|---|---|---|
| `/loop` | локально, у відкритій сесії | так | відкрита сесія Claude | 1 хвилина |
| desktop scheduled | локально, без сесії | так | увімкнена машина (сесія не потрібна) | за розкладом ОС |
| cloud `/schedule` | інфраструктура Anthropic | **ні (свіжа копія з git)** | нічого свого (машина може бути вимкнена) | 1 година |

Та сама таблиця друкується через `make matrix`.

Читати матрицю просто: що нижче рядок, то менше має бути ввімкнено на твоєму боці
(аж до вимкненої машини), але то менше хмара знає про твій локальний стан (аж до
повної сліпоти до незакоміченого).

## Головна пастка: хмара не бачить локальних файлів

Найдорожча помилка цього рівня - завести хмарну рутину над тим, чого нема в git.

Хмарна рутина (`/schedule`) щоразу бере **свіжу копію репозиторію з git**. Усе,
чого в git немає - під `.gitignore`, незакомічене, поза репозиторієм - для неї
**не існує**.

Worked-приклад просто в цьому демо:

1. Тека `drafts/` містить `example-note.md` з живими думками. Локально ти його
   бачиш.
2. Але `drafts/` стоїть у `.gitignore` (відкрий `.gitignore` - там рядок
   `drafts/`).
3. Заводимо рутину: `/schedule create "щодня 03:00" "підсумуй нотатки в drafts/"`.
4. О 03:00 рутина прокидається у хмарі, бере свіжу копію з git - а в ній теки
   `drafts/` немає. Підсумок виходить порожнім.

Це не баг рутини, це властивість рівня. Лікування одне: **хочеш, щоб хмара щось
побачила - спершу закоміть це.** Локальний `/loop` ту саму `drafts/` бачить без
проблем, бо читає робочу директорію наживо.

Повний розбір і `/schedule run` для перевірки - у `routines/README.md`.

## Setup

```bash
cd modules/7-execution-scale/7.5-background

make verify          # GREEN на чистому checkout: snippets store уже реалізований
make matrix          # надрукувати матрицю трьох рівнів
```

`make verify` тут **зелений** навмисно: це не red-on-checkout build. Зелений
`pytest` - конкретна ціль, яку `/loop`-рецепт опитує («крути, поки pytest
зелений»). Потрібен встановлений `claude` CLI для реального прогону рецептів.

## Як запустити

| Команда | Що робить |
|---|---|
| `make verify` | DoD-проба (`pytest -q`). ЗЕЛЕНО на чистому checkout - конкретна ціль для `/loop`. |
| `make matrix` | Друкує матрицю трьох рівнів розкладу (серце цього демо). |
| `make demo` | Друкує матрицю + виклик кожного рівня + наголос на хмарній пастці. |
| `make clean` | Прибрати кеші (`.pytest_cache`, `__pycache__`). |
| `make help` | Список таргетів. |

`make demo` нічого не запускає сам - slash-команди живуть усередині `claude`,
тож demo лише друкує кроки.

## Рецепти

Кожен рівень і кожна фонова механіка має окремий рецепт:

| Рецепт | Про що |
|---|---|
| `recipes/loop.md` | локальний `/loop` - опитувати локальну умову, поки не виконається; обидві форми виклику |
| `routines/README.md` | хмарна рутина `/schedule` - спека + worked-приклад пастки + `list/update/run` |
| `recipes/background.md` | `/background` (`/bg`) - відчепити цілу сесію; контраст з `Ctrl+B`; зв'язка з `/goal` |
| `recipes/dashboard.md` | дашборд `claude agents` - шість станів, групи, клавіші, регулярний аудит |

## Фонова сесія vs Ctrl+B

Дві схожі назви, різна поведінка - це важливо не плутати:

- **`/background` (`/bg`, `claude --bg`)** відчіплює **цілу сесію**. Вона працює
  без твоєї уваги, ти повертаєшся, коли захочеш.
- **`Ctrl+B`** ховає у фон **лише поточну роботу**, що зараз виконується всередині
  живої сесії. Сама сесія лишається на передньому плані.

Простими словами: `Ctrl+B` - про одну операцію, `/background` - про цілу сесію.
Супервайзер прибирає простійні **незакріплені** фонові сесії приблизно через
годину; закріплені (`Ctrl+T` у дашборді) лишаються. Повний рецепт із зв'язкою
`/background` + активний `/goal` (щоб сесія зупинилась сама) - у
`recipes/background.md`.

### Вбудовані запобіжники (довідка)

- **Термін життя 7 днів** - рутина/задача автоматично згасає через тиждень, щоб
  забуте не крутилось вічно.
- **Максимум 50 задач на сесію** - стеля проти лавини запланованих задач.
- **Jitter** - невеликий випадковий розкид часу запуску, щоб рутини не били всі
  одночасно.
- **`CLAUDE_CODE_DISABLE_CRON`** - змінна середовища, що глобально вимикає всі
  cron-рутини (аварійний рубильник).
- **Тверда стеля витрат - на тобі.** Запобіжники обмежують кількість і час, але
  не гроші - постав алерт на сплеск витрат в Anthropic Console.

## Як перенести у свій проєкт

1. Визнач рівень за матрицею: потрібен локальний стан робочої директорії - бери
   `/loop` чи desktop scheduled task; машина буває вимкнена і працюєш лише над
   закоміченим - бери cloud `/schedule`.
2. Перед хмарною рутиною перевір: усе, що їй треба бачити, **закомічено в git**?
   Якщо щось у `.gitignore` чи незакомічене - рутина цього не побачить.
3. Для AFK-сесії спаруй `/background` з активним `/goal` (бінарна умова зупинки),
   ізолюй прогін у git worktree на гілці `claude/...`.
4. Заведи звичку: раз на день `claude agents` - аудит проти забутих сесій. Постав
   алерт витрат в Anthropic Console - тверда стеля на тобі.
