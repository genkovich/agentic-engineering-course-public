# Рецепт: `/loop` - опитувати локальну умову, поки не виконається

`/loop` (loop - цикл) повторює один промпт чи slash-команду на повторюваному
інтервалі **всередині відкритої сесії**. Це найлокальніший рівень розкладу з
лекції 7.5.

Що про нього треба тримати в голові:

- **Живе всередині відкритої сесії.** Нова розмова - і цикл помирає. Закрив
  термінал чи перезапустив машину - цикл зник. Він не переживає рестарт.
- **Бачить локальні файли** робочої директорії як є: незакомічене, чернетки у
  `drafts/`, усе. Це його сила проти хмарної рутини.
- **Найменший інтервал - 1 хвилина.**

## Дві форми виклику

`/loop` має дві форми.

### 1. З явним інтервалом: `/loop <інтервал> <промпт>`

Запускає промпт кожні N хвилин/годин, поки ти не зупиниш або поки промпт сам не
вирішить, що далі немає сенсу.

```
claude
  /loop 30m реалізуй наступну todo-story і зупинись, коли pytest зелений
```

Тут зелена ціль конкретна - `make verify` (тобто `pytest -q`) у цьому демо вже
зелений, тож рецепту є на що спиратись:

```
claude
  /loop 5m прожени make verify; якщо зелено - доповідай і зупиняйся, інакше доправ і чекай наступного обороту
```

### 2. Самопаспейсинг: `/loop <промпт>` (без інтервалу)

Без інтервалу модель сама вирішує, коли робити наступний оборот - корисно для
«стеж і доповідай, коли стан зміниться»:

```
claude
  /loop стеж за make verify і доповідай, щойно стане зелено
```

## Чому саме `/loop` для локальної умови

Опитування локального стану («крути, поки тест зелений / поки файл зʼявиться /
поки білд пройде») - саме той випадок, де треба бачити робочу директорію наживо.
Хмарна рутина (`/schedule`, див. `../routines/README.md`) тут не підійде: вона
працює зі свіжою копією з git і локального стану не бачить.

## Запобіжники

- Зупинити цикл вручну можна в будь-який момент.
- Не лишай `/loop` без бінарної умови зупинки в промпті - інакше він крутитиме
  оберти й палитиме токени, поки ти не втрутишся. Тверда стеля витрат - на тобі
  (алерт на сплеск витрат в Anthropic Console).
- Спарувати з активним `/goal` (лекція 7.3): тоді сесія зупиниться сама, щойно
  стійка умова завершення виконається. Деталі - у `background.md`.
