# 7.3 · /goal - автономний фініш (demo)

Demo-проект для лекції **7.3 /goal: автономний фініш (Ralph у коробці)**
(Module 7 · Execution & Scale).

`/goal <умова>` - це вбудований Ralph: ти задаєш стійку умову завершення,
Claude крутить ходи сам, поки вона не виконається, а рішення «готово» виносить
не виконавець, а окрема свіжа модель-оцінювач за транскриптом розмови. Цей пакет
дає (1) **runnable** abstract substrate з вимірюваною задачею (нормалізація
тегів) і (2) головний навчальний артефакт - файл `completion-condition.md` з
доброю і слабкими умовами завершення.

## Що показує

- `/goal <умова>` як стійка умова завершення; перший хід робиться одразу - умова
  і є завданням.
- Окрема свіжа модель-оцінювач судить умову після кожного ходу і повертає
  бінарне «так/ні» з причиною.
- **Сліпа пляма оцінювача:** він судить тільки те, що Claude **написав** у
  транскрипт, а не реальний стан світу.
- Три частини здорової умови: вимірюваний кінцевий стан + явна перевірка, чий
  результат лягає в транскрипт + обмеження, що не повинно зламатись.
- Мʼякий запобіжник `or stop after N turns` (оцінюється з транскрипту,
  скидається при відновленні сесії) і ручне зняття `/goal clear`.

Задача в self-contained демо навмисне **абстрактна** (нормалізація тегів):
урок про вимірювану умову завершення і сліпу пляму оцінювача, а не про
конкретну фічу.

## Setup

```bash
cd modules/7-execution-scale/7.3-goal

make verify          # RED на чистому checkout: tags.py = NotImplementedError stub - це стартовий стан
```

`uv` підтягне `pytest` сам. Потрібен встановлений `claude` CLI для реального
прогону `/goal`. `models.py` і `store.py` закомічені готовими (залежності),
`tags.py` закомічений як заглушка - саме її `/goal` доводить до завершення.

## Як запустити

| Команда | Що робить |
|---|---|
| `make verify` | DoD-проба (`pytest -q`). Червоно на старті (`tags.py` = `NotImplementedError`), зелено після успішного `/goal`. |
| `make demo` | Друкує кроки `/goal` з доброю умовою з трьох частин (slash-команда живе всередині `claude`, тож не авто-ран). |
| `make demo-weak` | Друкує, як відтворити сліпу пляму оцінювача слабкою прозовою умовою. НЕ авто-ран. |
| `make clean` | Прибрати кеші (`.pytest_cache`, `__pycache__`). |
| `make help` | Список таргетів. |

## Здорова умова завершення

Щоб умову `/goal` не можна було випадково закрити прозою, вона має три частини:

1. **Вимірюваний кінцевий стан** - результат з однією однозначною відповіддю
   (результат тесту, код завершення збірки, порожня черга).
2. **Явна перевірка** - як Claude доводить цей стан і чий результат **лягає в
   транскрипт** (`pytest exits 0`, `git status` чисте).
3. **Обмеження** - те, що не повинно зламатись по дорозі (`git diff -- tests/`
   пустий, щоб модель не «дотягнула» умову, підправивши сам тест).

Добра умова для задачі цього демо:

```
/goal all tests in tests/test_tags.py pass, pytest exits 0, and git diff -- tests/ is empty, or stop after 12 turns
```

Повний розбір по частинах і чотири слабкі умови з поясненням, чому кожна
провалюється - у **[completion-condition.md](completion-condition.md)**. Це
головний артефакт цього демо.

## Сліпа пляма оцінювача

Оцінювач (за замовчуванням Haiku) **не запускає інструменти і сам не читає
файли**. Він судить рівно те, що Claude уже виклав у розмову. Це двосічно:
дешево і швидко - але умову можна **випадково обдурити** текстом. Якщо Claude
напише «усі тести пройшли», а насправді їх не запускав, оцінювач прочитає цей
рядок і може закрити ціль. Він перевіряє не реальність, а те, що **сказано** в
транскрипті.

| | слабка умова (проза) | добра умова (3 частини) |
|---|---|---|
| Приклад | `/goal the code is correct` | `/goal all tests in tests/test_tags.py pass, pytest exits 0, and git diff -- tests/ is empty, or stop after 12 turns` |
| Слід у транскрипті | немає - лише слова Claude | вивід `pytest` + код завершення |
| Що бачить оцінювач | «implementation looks correct» | «pytest exits 0» / «1 failed» |
| Результат | закриває ціль на прозі, `make verify` лишається червоним | закриває ціль лише на реальному зеленому тесті |

`make demo-weak` друкує, як це відтворити: слабка умова закриває ціль, а
`make verify` лишається червоним - бо реальність ніхто не перевіряв. Ліки -
не красивіша проза, а машинна перевірка, чий результат лягає в транскрипт.

## Очікуваний вивід

Добрий шлях (`make demo` → всередині `claude`), ≈3-5 ходів:

```
◎ /goal active   turns: 1   tokens: …      ← панель зʼявляється одразу, перший хід без окремого промпту
Хід 1   Claude пише normalize_tag/count_by_tag; pytest → кілька кейсів падають
        evaluator: "no - tests/test_tags.py: 2 failed; not yet exit 0"
Хід 2   Claude доправляє обрізання дефісів з країв; pytest → зелено
        evaluator: "yes - pytest exited 0, git diff -- tests/ empty"
✓ goal achieved   (ціль очищається сама, відмітка лягає в транскрипт)
```

Перевірка результату:

```bash
make verify                       # зелено
git log --oneline -1              # feat: tag normalization + count_by_tag
git diff -- tests/                # пусто (обмеження умови дотримано)
```

Слабкий шлях (`make demo-weak`): оцінювач закриває ціль на прозі, але
`make verify` лишається червоним - наочна сліпа пляма.

## Покриття концептів лекції

| Концепт лекції | Де у демо |
|---|---|
| Умова з трьох частин (вимірюваний стан + явна перевірка + обмеження) | `completion-condition.md`, добра умова для SNIP-2 |
| Сліпа пляма оцінювача (судить транскрипт, не світ) | `completion-condition.md` + `make demo-weak` (`/goal the code is correct`) |
| Мʼякий запобіжник `or stop after N turns` | хвіст доброї умови; розбір у `completion-condition.md` |
| `/goal clear` (ручне зняття; синоніми) | `make demo` (останній крок) |
| Завершення судить за транскриптом, не виконавець | `make demo` (причина оцінювача після кожного ходу) |
| Вимірюваний кінцевий стан як DoD | `tasks/story-snip-2.md` → `pytest tests/test_tags.py` зелений |

## Як перенести у свій проєкт

1. Візьми одну story з вимірюваним DoD (зелений тест, код 0 збірки - щось з
   однозначною відповіддю).
2. Напиши умову з трьох частин: вимірюваний стан + явна перевірка, чий результат
   лягає в транскрипт + обмеження. Додай мʼякий `or stop after N turns`.
3. `/goal <умова>`. Стеж за панеллю `◎ /goal active` і причиною оцінювача після
   кожного ходу; `/goal clear`, якщо пішло не туди.
4. Для нічного прогону постав тверду межу витрат окремо (алерт у Anthropic
   Console або ліміти організації) - мʼякого `or stop after N` замало.
