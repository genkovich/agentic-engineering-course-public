# CLAUDE.md · Dynamic workflows demo (Lecture 7.4)

Мінімальний контекст для self-contained демо динамічних workflows. Задачі
навмисно абстрактні (пошук / дедуп / експорт сніпетів) - урок про те, як
незалежність робить паралельний fan-out безпечним, а не про бізнес-фічу.

## Стек

- Python 3.12, `pytest`. Без бізнес-залежностей (тільки стандартна бібліотека).
- Код: `src/snippets/`. Тести: `tests/test_*.py`.
- Скрипти оркестрації: `.claude/workflows/*.mjs` (плоский JavaScript, Node).

## Конвенції

- **Працюючі частини** - `models.py` (`Snippet`), `store.py` (`SnippetStore`),
  `tags.py` (`normalize_tag`): закомічені готовими, це залежності задач.
- **Задачі** - `search.py`, `dedupe.py`, `export.py`: три НЕЗАЛЕЖНІ заглушки з
  `NotImplementedError`. Кожна пише рівно у свій файл.
- **Atomic commit per story** - закрита story у `tasks/` = окремий commit з
  префіксом `feat:` або `fix:`.

## HARD RULE - хто пише код

- **Координатор лише розбиває / делегує / збирає - код пишуть тільки виконавці.**
  Скрипт workflow тримає план, цикл і проміжний стан; сам він не читає, не пише
  файлів і не запускає команд. Усю роботу з файлами й тести робить кожен
  `agent()` (виконавець) у власному контексті.
- **Виконавці не торкаються чужих файлів.** Агент сторіс SNIP-3 пише тільки
  `search.py`, SNIP-4 - тільки `dedupe.py`, SNIP-5 - тільки `export.py`. Перетин
  множин файлів = гонка за запис, тому заборонено.

## Не робити

- Не змінювати `tests/` - якщо тест падає, фіксити код, не тест
  (`git diff -- tests/` має лишатись пустим).
- Не змінювати story-файли в `tasks/` - це контракти.
- Не комітити `__pycache__/`, `.pytest_cache/`, `.venv/`.
