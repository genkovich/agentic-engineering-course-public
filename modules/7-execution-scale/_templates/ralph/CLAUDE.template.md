# CLAUDE.md · інструкції проекту для Ralph-прогону

> Шаблон. Скопіюй у `CLAUDE.md` в корені репозиторію і заповни плейсхолдери `<…>`.
> Тримай файл тонким - це довговічний контекст, який модель перечитує щоходу.
> Що довший файл, то більше шуму в кожній ітерації.
>
> Плейсхолдери: `<STACK>` (наприклад `Python 3.12 + pytest`), `<CODE_DIR>` (тека коду),
> `<TEST_DIR>` (тека тестів), `<TEST_CMD>` (команда тестів, наприклад `pytest -q` /
> `go test ./...` / `npm test`).

## Стек

- `<STACK>`.
- Код: `<CODE_DIR>/`. Тести: `<TEST_DIR>/`.
- Тестова команда: `<TEST_CMD>` (одна команда, що повертає код 0 на зеленому стані).

## Конвенції

- **Atomic commit per story** - кожна закрита історія в `tasks/tracker.md` = окремий
  коміт з префіксом `feat:` (нова фіча) або `fix:` (виправлення). Один коміт - одна історія.
- **Test-first** - тест існує ДО реалізації; код пишемо так, щоб тест став зеленим.

## Не робити

- Не змінювати `<TEST_DIR>/` - якщо тест падає, виправляти код, не тест.
- Не змінювати story-файли в `tasks/` - це контракти задач.
- Не комітити артефакти прогону: `cost.log`, `DONE`, кеші й тимчасові теки твого стека.
- Не підвищувати дозволи понад `acceptEdits` (модель застосовує правки файлів, але не
  виконує довільних команд без явного дозволу). Жодних `--dangerously-skip-permissions`.
