# 9.5 Code review — screencast prompts

Детальні 🎬-блоки під обидва скринкасти лекції 9.5. Статус-маркери:
`[ готово ]` фікстура зібрана й перевірена; `[ запис ]` чекає на лектора.

Перед кожним дублем: `make reset`, потім `cd sandbox`, потім `claude` з кореня
пісочниці (агент бере `.claude/` і `CLAUDE.md` саме звідти). Активна гілка —
`feat/reminders`, на ній лежить PR-in-progress із трьома дефектами.

---

## 🎬 #1 — Тур локального стеку + handoff `[ запис ]`

**Секція лекції:** 2 (локальне рев'ю в сесії)
**Режим фікстури:** `make sandbox`
**Pre-state:** `feat/reminders` checked out; `git diff main...HEAD` показує
дифф з off-by-one, дубльованим `format_short` і command injection;
`make test` — червоний (off-by-one).
**Тривалість:** ~3:30

### Послідовність

1. **Контекст (голос, ~20с).** «У нас відкритий PR `feat/reminders` — додає
   desktop-нагадування. Прогнали тести — один червоний. Перш ніж кликати
   рев'юера-людину, проженемо локальний прохід прямо в сесії.»
   ```bash
   git log --oneline main..feat/reminders   # один коміт PR
   make test                                # RED: off-by-one на межі вікна
   ```

2. **`/code-review --comment` (~50с).** У сесії:
   ```
   /code-review --comment
   ```
   Агент дивиться `git diff main...HEAD`, знаходить off-by-one у `due_within`
   (`reminders.py`) і постить інлайн-коментар у PR.
   - 🎬 Покажи в кадрі знахідку P1 з посиланням `reminders.py:due_within`.
   - ⚠️ Інлайн-коментар у PR потребує реального origin (локальний bare його не
     приймає). Для кадру або підстав GitHub origin (як у 9.4), або зведи до
     стдаут-знахідки й скажи голосом «на справжньому origin це лягло б
     коментарем у PR».

3. **`/simplify` застосовує фікс (~40с).**
   ```
   /simplify
   ```
   Агент згортає дубльований `format_short` у спільний хелпер `_when(due)`.
   ```bash
   git diff src/tasks/model.py    # один формат-хелпер замість двох копій
   ```
   - 🎬 Покажи `git diff` до/після: дві копії ладдера → один виклик.
   - Голос: «`/simplify` — це лише якість. Він не шукає багів — для цього
     `/code-review`.»

4. **`/codex:review` — Codex-плагін у сесії (~50с).** Контраст другого рушія
   рев'ю в тій самій сесії:
   ```
   /codex:review
   ```
   - 🎬 Покажи, що Codex теж ловить injection/межу — це не один LLM «на віру».
   - ⚠️ Пререк: встановлений `codex` CLI і Codex-плагін Claude Code.

5. **Свіжий прохід підбирає коментарі PR і `--fix` (~40с).** Нова сесія/прохід:
   ```
   /code-review --fix
   ```
   Агент читає коментарі PR, застосовує фікс off-by-one у робоче дерево.
   ```bash
   make test                      # тепер GREEN
   ```
   - 🎬 Закрий цикл: червоний тест → фікс із рев'ю → зелений.

**Voice notes.** Лейтмотив — «локальний прохід дешевий і швидкий, ганяй його до
того, як кликати людину». Три команди = три фокуси: коректність, якість,
безпека. Не змішуй їх в одному виклику (для зведеного є `/codereview`).

## 🎬 #2 — `/security-review` глибше `[ запис ]`

**Секція лекції:** 3 (безпековий прохід)
**Режим фікстури:** `make sandbox`
**Pre-state:** той самий `feat/reminders`; у диффі `notify_desktop` з
`os.system(... title ...)`.
**Тривалість:** ~3:00
**Це headline-скринкаст лекції.**

### Послідовність

1. **Запуск (~40с).**
   ```
   /security-review
   ```
   Агент знаходить command injection: `task["title"]` тече в
   `os.system("notify-send ... '%s'")` у `reminders.py:notify_desktop`.
   - 🎬 Покажи знахідку P0 з класом «command injection» і прикладом експлойта:
     назва завдання `'; rm -rf ~ ;'` виконається шеллом.
   - 🎬 Покажи запропонований фікс: `subprocess.run([...], shell=False)` зі
     списком аргументів.

2. **Кастомізація через копію (~60с).** Відкрий
   `.claude/commands/security-review.md` (вже лежить у фікстурі) і покажи, що
   це проєктна копія вбудованого `/security-review` — у неї дописані пріоритети
   під threat-model репо (інʼєкції, секрети, path traversal = P0).
   - 🎬 У кадрі: дописати один рядок у блок «Фокус», зберегти, перезапустити
     `/security-review` — прохід тепер явно перевіряє додане.
   - Голос: «рев'ю — це конфіг проєкту, його версіонують і підлаштовують, а не
     тримають у голові.»

3. **Чесна межа (~50с, голос + кадр).** Запусти поряд детермінований шар:
   ```bash
   make test                      # ловить off-by-one, але МОВЧИТЬ про injection
   ```
   - 🎬 Підкресли: тест зелений на injection — бо тести перевіряють поведінку,
     не безпеку. LLM-рев'ю ловить патерн, але теж не дає гарантії.
   - Голос: «LLM-рев'ю **доповнює**, а не **заміняє** детерміновані інструменти.
     У CI поряд мають жити секрет-скан і SAST. Комбінуй три шари — тести,
     детермінований скан, LLM-рев'ю — а не обирай один.»

**Voice notes.** Не продавай LLM-рев'ю як срібну кулю. Сила — у швидкому
ловінні очевидного й у тому, що це версіонований конфіг. Слабкість — немає
гарантій, тому поряд завжди детермінований шар.
