# /code-review — прохід коректності

Це проєктна обгортка над вбудованим `/code-review`: вона задає контекст саме
цього репо, а саму перевірку виконує вбудована команда. Гони її на діфі
`feat/reminders` проти `main`.

## Що зробити

1. Зібрати дифф гілки: `git diff main...HEAD`.
2. Пройтись по змінах, шукаючи **логічні** баги (P1): хибні межі, off-by-one,
   неопрацьовані порожні/крайні випадки, проґавлений `return`.
3. Звіритися з `## Review guidelines` у `CLAUDE.md` (пріоритети P0/P1/P2).
4. Видати знахідки з посиланнями `file:line` і пропозицією фіксу.

## Аргументи

- `--comment` — запостити знахідки інлайн-коментарями в PR (потребує відкритого PR).
- `--fix` — застосувати запропоновані правки у робоче дерево після рев'ю.

## Очікувана знахідка на цьому фікстурі

`due_within` у `reminders.py` використовує строге `<`, тож завдання з терміном
рівно на межі вікна тихо випадає. Має бути інклюзивне `<= days`. Це P1.

## Anti-patterns

- Не чіпай питання стилю/дублювання — це робота `/simplify`.
- Не шукай вразливостей — це робота `/security-review`.
