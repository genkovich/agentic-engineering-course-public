# /security-review — прохід безпеки

Кастомізована копія вбудованого `/security-review`. Лежить файлом у проєкті
навмисно: на скринкасті ми показуємо, що цей прохід можна підлаштувати під
свій threat-model, дописавши пріоритети нижче.

## Фокус (під threat-model цього репо)

- **Інʼєкції** — неперевірений ввід, що тече у shell / SQL / шлях / eval.
- **Секрети в коді** — хардкоднуті ключі, токени, паролі.
- **Path traversal** — користувацький шлях без нормалізації.

Усе перелічене — **P0** за `## Review guidelines` у `CLAUDE.md`: блокує мердж.

## Що зробити

1. Зібрати дифф гілки: `git diff main...HEAD`.
2. Для кожної зміни спитати: чи тече сюди недовірений ввід? куди він іде далі?
3. Видати знахідки з `file:line`, класом вразливості та конкретним фіксом.

## Очікувана знахідка на цьому фікстурі

`notify_desktop` у `reminders.py` підставляє `task["title"]` прямо у
`os.system("notify-send ... '%s'")`. Назва завдання — недовірений ввід, тож
заголовок `'; rm -rf ~ ;'` виконається шеллом. Клас: **command injection**,
P0. Фікс: `subprocess.run([...], shell=False)` зі списком аргументів.

## Чесна межа

LLM-рев'ю безпеки ловить очевидні патерни, але **не замінює** детерміновані
інструменти: секрет-скан і SAST у CI. Комбінуй їх, а не обирай одне.
