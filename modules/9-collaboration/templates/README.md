# Collaboration templates (copy-ready)

Готові артефакти для **твого** репозиторію. Це не демо-фікстури (ті лежать у
`9.1`–`9.6` і будуються в пісочниці), а production-ready файли, які можна
скопіювати у корінь власного проєкту й одразу користуватись. Вони багатші за
мінімальні демо: тут зібрано все, що по шматках показано в лекціях 9.1–9.6.

## Що тут

| Файл | Звідки | Що дає |
|---|---|---|
| `CLAUDE.md` | 9.1 + 9.4 | Етикет репо для Claude: Git-конвенції + правила Pull requests |
| `AGENTS.md` | 9.6 | Спільні правила для агентів-рев'юерів (Claude / Codex / Copilot): пріоритети P0/P1/P2 |
| `.claude/settings.json` | 9.1 + 9.3 + 9.4 | Дозволи: `deny` на небезпечні команди, `ask` на мердж PR, `allow` на безпечну рутину |
| `.claude/hooks/block-env.sh` | 9.1 | PreToolUse-хук: блокує спробу додати `.env` у коміт |
| `.claude/hooks/block-main-push.sh` | 9.3 | PreToolUse-хук: блокує прямий `git push` у `main` |
| `.github/pull_request_template.md` | 9.4 | Шаблон тіла PR: «Що змінилось», «Навіщо», «Як перевірити», `Closes #` |

## Як застосувати

1. Скопіюй потрібні файли у корінь свого репозиторію (зберігаючи структуру тек
   `.claude/` і `.github/`).
2. Зроби хуки виконуваними: `chmod +x .claude/hooks/*.sh`.
3. Підлаштуй `CLAUDE.md` і `AGENTS.md` під свій проєкт (секція «Project context»
   в `AGENTS.md` — обов'язково під себе).
4. Перевір, що хуки спрацьовують: спробуй `git add -f .env` (має заблокувати) і
   `git push origin main` (має попросити named-гілку).

Хукам потрібен `jq`. Дозволи й хуки доповнюють, а не заміняють перевірки в CI
(тести, секрет-скан, SAST).
