# MCP чи CLI · чек-лист довіри

Дві шпаргалки, які варто тримати поруч з власним `.mcp.json`: коли сервер взагалі
варто підключати (чек-лист довіри) і коли замість MCP краще взяти CLI (матриця).

## Чек-лист п'яти перевірок перед підключенням

Працює як код-рев'ю нової залежності. Особливо обов'язковий для community-серверів.

1. **Хто автор** - вендор сервісу, команда протоколу чи незнайомий акаунт?
2. **Чи живий проєкт** - дата останнього коміту, реакція на issues. Сервер без
   підтримки відстане від специфікації за пів року.
3. **Скільки tools віддає** - це контекстна вартість. Сервер на 5 tools і на 100
   - різні рішення з різною ціною definitions у кожному запиті.
4. **Які права просить** - читання чи запис, який scope токена, чи є read-only режим.
5. **Чи є локальний варіант** - локальний stdio можна прочитати очима і зафіксувати
   версію; remote - чужа інфраструктура, код якої змінюється без твого відома.

## Матриця MCP vs CLI

| Бери MCP, коли... | Бери CLI (через Bash), коли... |
|---|---|
| потрібен стан сесії між викликами (браузер тримає вкладку) | виклик разовий: одна команда - один результат |
| потрібні структуровані результати без парсингу тексту | потрібна скриптованість: пайпи, jq, той самий скрипт у CI |
| у сервісу немає CLI (Figma Dev Mode, Notion, Linear) | утиліта зріла й знайома моделі (gh, psql) |
| авторизація через OAuth з оновленням токенів | важлива нульова постійна ціна: Bash уже в контексті |

## Чому «підключу про запас» - антипатерн

Definitions кожного підключеного сервера входять у **кожен запит** сесії, навіть
коли сервер мовчить. Виміряно: 23 tools Playwright MCP - близько 3.5 тисячі
токенів описів; браузерна задача на 10 кроків - ~114K токенів через Playwright MCP
проти ~27K через playwright-cli. Орієнтир для хостів: коли описи інструментів
займають понад 1-5% контекстного вікна - час вмикати progressive discovery або
чистити конфіг. `claude mcp list` раз на тиждень показує, хто в конфігу зайвий.
