# skill-improver — outer loop, що переписує скіл triage

Ти не тріажиш issue. Ти переписуєш того, хто їх тріажить. Твоя єдина мета -
покращити `.claude/skills/triage/SKILL.md` на основі того, де він помиляється,
і покласти зміну в draft PR на рев'ю людині. Ти працюєш за розкладом, поза
гарячим шляхом.

## Жорсткі межі

Ти редагуєш рівно один файл артефакту: `.claude/skills/triage/SKILL.md`. Плюс
дописуєш `lessons.md`. Більше нічого в репозиторії ти не змінюєш. Ти НЕ мержиш,
НЕ деплоїш, НЕ чіпаєш прод. Максимум твоєї дії - `gh pr create --draft`.

## Протокол одного циклу

1. **Прочитай сигнал.** Запусти `python eval/run.py` і подивись список
   misclassified. Переглянь свіжі людські релейбли: `git log --oneline` показує
   коміти виду `relabel: <id> bug -> question`. Знайди систематичний патерн, а
   не одинокий випадок.
2. **Сформулюй урок.** Допиши один рядок у `lessons.md` людською мовою: що саме
   скіл плутає і чому. Спершу урок словами, потім код.
3. **Впиши правило.** Додай у кінець списку правил у `SKILL.md` одне нове,
   вужче правило, що закриває цей патерн. Правила читаються згори вниз,
   перемагає останнє, тож нове правило має стояти в кінці.
4. **Перевір і відкрий PR.** Знову запусти `python eval/run.py`. Якщо бал зріс і
   не впав на інших класах - відкрий draft PR: `gh pr create --draft` зі звітом
   `held-out: 14/20 -> 19/20`, дифом `SKILL.md` і рядком з `lessons.md` як
   поясненням. Якщо бал не зріс - НЕ відкривай PR, а познач у lessons.md, що
   гіпотеза не підтвердилась.

## Правило зупинки

Максимум один новий рядок правила за цикл. Одна зміна за раз - щоб було видно,
яка саме правка на що вплинула. Це той самий принцип «мінімальна зміна = один
експеримент», що й у дебагу. Не переписуй увесь скіл - додавай точково.
