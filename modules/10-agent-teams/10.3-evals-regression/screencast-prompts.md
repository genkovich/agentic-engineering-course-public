# Screencast-сценарії · 10.3 Evals і регресійне тестування агентів

П'ять скринкастів, нумерація збігається з тілом лекції (#1-#5). Скринкасти - ЛИШЕ
живі прогони; статичні файли (frontmatter агента, check.py, lint.py, rubric.md,
promptfooconfig.yaml) показуються слайдами - див. блоки «Показати» у тілі лекції.

Наскрізна арка: «збудували агента → написали йому тест руками → зламали конфіг →
тест упіймав → віддали все Promptfoo». Центральна теза: **детермінований грейдер
над недетермінованим агентом**.

Спільна передумова:

```bash
cd ~/sources/agentic-engineering-course/modules/10-agent-teams/10.3-evals-regression
make lint           # 0 токенів - зелено за секунду
# для #1-#5 потрібен claude CLI; прогони агента коштують токени
```

> Кожен крок із `claude -p` / `promptfoo eval` жене **реального** агента:
> недетерміновано, плануй 2-3 дублі.

---

## 🎬 Скринкаст #1 (~2 хв) - агент з нуля і перший живий прогін

- **Поверхня:** порожній `.claude/agents/`, `src/discount.js`.
- **Pre-state:** чистий checkout; ro-reviewer.md ще «не написаний» (для кадру:
  тимчасово прибери файл, потім створюй у кадрі; вміст - з тіла лекції).
- **Тригеримо:**
  1. `cat src/discount.js` - проєкт, 5 рядків: модуль знижок.
  2. Створюємо `.claude/agents/ro-reviewer.md` у редакторі: frontmatter поле за
     полем (name → description → tools → model), потім body.
  3. `claude -p "Зроби рев'ю src/discount.js" --agent ro-reviewer` - перше живе
     рев'ю в терміналі: зауваження + вердикт WARN.
- **Кадр-висновок:** агент - це markdown-файл у репозиторії. Конфігурація, яку
  можна зламати так само тихо, як код.

---

## 🎬 Скринкаст #2 (~2.5 хв) - перший тест руками + red-green + лінт

- **Поверхня:** `eval/check.py`, `eval/broken/ro-reviewer.md`, `eval/lint.py`.
- **Pre-state:** робоче дерево чисте (`git status`); check.py показано слайдом
  ДО скринкасту.
- **Тригеримо:**
  1. `python3 eval/check.py` - PASS: рев'ю з вердиктом є, src/ незайманий.
  2. `cp eval/broken/ro-reviewer.md .claude/agents/ro-reviewer.md` - «хтось
     покращив» рев'юера (+Write, +Edit).
  3. `python3 eval/check.py` - FAIL: «агент ЗМІНИВ код» + список змін у кадрі.
  4. `git checkout .claude/agents/ro-reviewer.md && python3 eval/check.py` - PASS.
  5. `make lint` - той самий диф tools спіймано за секунду і за нуль токенів;
     потім ще раз red-green лінтом (cp broken → `make lint` червоний → checkout).
- **GUARD-кадр:** у FAIL-прогоні мусить бути видно і рядок «агент ЗМІНИВ код»,
  і сам список змін - без цього причинність «конфіг → поведінка» не читається.
- **Кадр-висновок:** ми не зламали жодного рядка коду продукту - лише
  конфігурацію агента. Тест на три десятки рядків це впіймав. Лінт ловить
  дешевше, але бачить лише текст конфігурації.

Озвучка: зламаний агент клює на провокацію не щоразу (недетермінізм) - плануй дублі.

## 🎬 Скринкаст #3 (~1.5 хв) - суддя руками і його розкид

- **Поверхня:** `eval/rubric.md`, `eval/judge.py`, `review.md` від #2.
- **Pre-state:** `review.md` існує (лишився після check.py); рубрику показано
  слайдом до скринкасту.
- **Тригеримо:**
  1. `cat review.md | head` - ось текст, який детермінованим скриптом не оціниш.
  2. `python3 eval/judge.py` - JSON: `{"score": 1.0, "reason": "..."}`.
  3. `python3 eval/judge.py` ще раз - бал може відрізнятись (0.5 ↔ 1.0) - розкид
     судді у кадрі (якщо не мигнув - сказати голосом, що мигає).
- **Кадр-висновок:** суддя - це ще один claude -p із рубрикою. Недетермінований,
  тому поріг і калібрування, а не сліпа віра одному балу.

## 🎬 Скринкаст #4 (~2.5 хв) - Promptfoo: той самий кейс без самопису

- **Поверхня:** `promptfoo/promptfooconfig.yaml`, `provider.py`, `check_clean.py`
  (усі показані слайдами ДО скринкасту - в кадрі лише прогони).
- **Pre-state:** `cd promptfoo`; `npm ci` уже зроблено.
- **Тригеримо:**
  1. `npx promptfoo@latest eval --no-cache` - PASS: regex + python + llm-rubric.
  2. `BREAK=1 npx promptfoo@latest eval --no-cache` - зламаний агент: python
     червоніє («агент ЗМІНИВ код у src/»), rubric теж.
  3. `npx promptfoo@latest view` - веб-переглядач: поруч зелений і червоний
     прогони, кожен асерт розгортається з reason.
- **Кадр-висновок:** три наші скрипти стали трьома рядками asserts. Принцип не
  змінився - змінився масштаб інструмента: матриця, історія, паралельність, view.

## 🎬 Скринкаст #5 (~2 хв) - сьют: решта п'ять кейсів

- **Поверхня:** `promptfoo/suite/promptfooconfig.yaml` (показаний слайдом),
  `suite/graders/*.py`.
- **Pre-state:** `cd promptfoo/suite && bash setup.sh` - чисті workdir-и.
- **Тригеримо:**
  1. `npx promptfoo@latest eval --no-cache` - п'ять кейсів один за одним
     (maxConcurrency: 1); у кадрі видно trajectory-асерти route-кейса і
     python-грейдери.
  2. `npx promptfoo@latest view` - матриця: кейс × асерти.
- **Дивимось:** `tdd-three-commits` може мигнути - чесно лишаємо в кадрі
  (ілюстрація глави про надійність).
- **Кадр-висновок:** шість кейсів - шість конфігів під захистом; вечірній
  `make evals` відповідає на питання «чи все ще працює те, що працювало вчора».
