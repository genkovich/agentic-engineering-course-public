## 🎬 Скринкаст #1 (~1.5 хв) - reproduce-first: дубль-requeue у queue

**Поверхня:** `packages/queue/consumer.js` (пісочниця 10.1) - схований баг повторної постановки.
**Що доводить:** цикл reproduce → root cause → fix → verify виконується одним промптом.

- **Pre-state:** `node --test packages/queue` - зелений; баг наявними тестами не ловиться.
- **Тригеримо:**
  > У packages/queue повідомлення після невдалої обробки інколи потрапляє в чергу двічі.
  > Спершу напиши failing test, який стабільно відтворює дубль. Потім знайди root cause і виправ.
  > Симптом не гаси: поясни причину перед фіксом.
- **Дивимось:** агент пише тест на дубль, той червоніє; агент пояснює причину і робить
  мінімальний фікс; тест і решта сьюту зеленіють.
- **Кадр-висновок:** увесь цикл в одному промпті: відтворив → пояснив причину → виправив →
  перевірив тим самим тестом.

## 🎬 Скринкаст #2 (~1 хв) - ризикована гіпотеза → відкіт → інший підхід

**Поверхня:** той самий `consumer.js`; СВІЖИЙ `make sandbox` (баг з #1 ще на місці).
**Що доводить:** /rewind робить провалену гіпотезу дешевою - один відкіт замість брудного каталогу.

- **Pre-state:** `git status` чистий; `node --test packages/queue` зелений (прихований баг живий).
- **Тригеримо:**
  > Гіпотеза: дубль виникає через повторний nack. Перепиши обробку помилок у consumer.js:
  > один try/catch і єдиний ack наприкінці.
  - тест на дубль (написати як у #1 або тримати з попереднього дубля) лишається червоним;
  - подвійний Esc на порожньому вводі → **Restore code and conversation**.
- **Дивимось:** правки зникли з файлів, розмова повернулась до точки перед гіпотезою; другу
  гіпотезу формулюємо без сміття від першої.
- **Кадр-висновок:** провалена гіпотеза коштує один відкіт, а не брудний каталог і забитий контекст.

## 🎬 Скринкаст #3 (~2 хв) - агент пише reproduce-скрипт, bisect знаходить коміт

**Поверхня:** пісочниця ЦЬОГО пакета (`make setup`).
**Що доводить:** ручний перебір 16 комітів не потрібен - агент формулює баг як тест `exit 0/1`
і дає бісекції звузити пошук за ~4 кроки (log2(16) = 4).

- **Pre-state:**
  - `git log --oneline | head` - 16 комітів звичайного вигляду;
  - `node -e "console.log(require('./src/invoice').buildInvoice([{price:19.99,qty:3}],{discountPercent:10,taxPercent:8.25}))"`
    → на HEAD видно `total: 58.42`, а бухгалтер очікує `58.43`;
  - `node --test` - сьют зелений: наявні тести баг не ловлять.
- **Тригеримо** (ідентично `Тригеримо` в тілі лекції):
  > Баг: інвойс 19.99 × 3 зі знижкою 10% і податком 8.25% повертає total 58.42, а має 58.43.
  > Напиши мінімальний reproduce-скрипт без залежностей: exit 0, якщо total правильний, і exit 1,
  > якщо ні. Тримайся стабільного публічного buildInvoice, щоб скрипт працював і на старих комітах.
  > Потім знайди винний коміт через git bisect run і покажи його диф. Нічого не виправляй -
  > тільки локалізуй.
- **Дивимось:**
  1. агент пише короткий reproduce-скрипт (node, `buildInvoice`, порівняння з 58.43, exit-код);
  2. `git bisect start HEAD <перший-коміт>`, тоді `git bisect run ...`;
  3. серія `Bisecting: N revisions left ...`, чотири прогони скрипта; наприкінці
     **`refactor: extract discount application` is the first bad commit**;
  4. агент читає диф коміту #9 і пояснює зрізаний округленням цент;
  5. `git bisect reset` - повернутись на main.
- **Кадр-висновок:** агент шукав не по коду, а по історії: reproduce-скрипт плюс бісекція дали
  винний коміт за чотири кроки.
- **Fallback (детермінований дубль):** `make bisect` з кореня пакета друкує iterations,
  знайдений і seed-коміт та PASS - годиться як вставка, якщо живий take не вийшов.

## 🎬 Скринкаст #4 (~1.5 хв) - зламаний хук: драбина знаходить винного

**Поверхня:** пісочниця 10.1 + підкладений PreToolUse-хук (рецепт нижче).
**Що доводить:** спадна драбина (/context → /hooks → `--debug hooks` → `--safe-mode`)
перетворює «агент не хоче писати файли» на «ось хук, ось exit 2».

**Рецепт зламаного хука** (покласти в пісочницю ДО запуску `claude`; хук мовчки блокує Write):

```bash
cd sandbox
mkdir -p .claude/hooks
cat > .claude/hooks/block-write.sh <<'EOF'
#!/usr/bin/env bash
# imitates a stale "protect" hook someone forgot about: silently blocks Write
exit 2
EOF
chmod +x .claude/hooks/block-write.sh
cat > .claude/settings.json <<'EOF'
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [{ "type": "command", "command": ".claude/hooks/block-write.sh" }]
      }
    ]
  }
}
EOF
```

- **Pre-state:** просимо агента поправити коментар у будь-якому файлі - правка не відбувається.
- **Тригеримо** (драбину згори):
  1. `/context` - усе завантажене, підказки нема;
  2. `/hooks` - хук видно, але причина відмови не очевидна;
  3. перезапуск `claude --debug hooks` і той самий промпт на правку.
- **Дивимось:** у debug-виводі подія PreToolUse, matcher `Write|Edit` і exit-код 2 - блокує саме
  наш хук; контрольний постріл `claude --safe-mode`: правка проходить.
- **Кадр-висновок:** «агент не хоче писати файли» за дві хвилини стало «ось хук, ось exit 2» -
  без жодного вгадування.
- **Прибирання:** видалити `.claude/settings.json` і `.claude/hooks/` або перезібрати пісочницю.

## 🎬 Скринкаст #5 (~1.5 хв) - три тіммейти проти flaky-тесту

**Поверхня:** `packages/reports/__tests__/summary.flaky.test.js` (пісочниця 10.1) - тест з
Math.random, падає ~50/50.
**Що доводить:** конкурентні гіпотези збігаються до кореня швидше за послідовний перебір теорій.
**Передумова:** `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` (env або settings.json) - режим experimental.

- **Pre-state:** `node --test packages/reports` двічі-тричі поспіль - то зелений, то червоний.
- **Тригеримо:**
  > Тест у packages/reports падає через раз. Спавни трьох тіммейтів із різними гіпотезами:
  > недетермінований вхід, залежність від часу, спільний стан між тестами. Хай спростовують
  > одне одного і зведуть консенсус у findings.md.
- **Дивимось:** тіммейти обмінюються аргументами; консенсус сходиться до Math.random у самому
  тесті; фікс робить вхід детермінованим, десять прогонів поспіль зелені.
- **Кадр-висновок:** три незалежні слідчі зійшлись на корені швидше, ніж одна сесія перебирала б
  ті самі теорії по черзі.
- **Recording-caveat:** Agent Teams експериментальні - записувати на pinned-версії Claude Code,
  перед зйомкою звірити флоу з live-доками (див. Sources лекції, version-pins).

## Safety-нотатки

- **Read-only локалізація в #3.** Промпт прямо каже «нічого не виправляй». `git bisect` робить
  checkout різних комітів, але не змінює історію; наприкінці обов'язковий `git bisect reset`.
  Якщо агент лишив бісекцію відкритою - `cd sandbox && git bisect reset`.
- **Пісочниці одноразові.** Уся дія в git-ignored `sandbox/`; безлад лікується перезбіркою.
- **Без токенів у бісекції.** `git bisect run` не звертається до моделі: це локальний git+node.
  Модель потрібна лише щоб написати reproduce-скрипт і прочитати диф.
- **Не показувати `.culprit`.** Файл `sandbox/.culprit` містить хеш відповіді (для `make bisect`).
  На записі його не відкривати - зникає інтрига пошуку.
- **Хук-фікстура #4 - лише в пісочниці.** Не клади block-write.sh у власний `$HOME`; після дубля
  прибери `.claude/settings.json` з пісочниці.

## Recording runbook

1. Перед кожним дублем - свіжа пісочниця (`make sandbox` у 10.1 / `make setup` тут).
2. `cd sandbox`, тоді `claude` - щоб конфіг і git бачились із CWD пісочниці.
3. У #3 показати симптом (`total: 58.42`) і зелений `node --test` ДО промпту.
4. Формат виводу `git bisect` залежить від версії git; кроків ~4 на 16 комітів.
5. Для #5 виставити `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` і звірити teams-флоу з live-доками.
6. Глобальний конфіг (`$HOME`, MCP, плагіни) на запис не чіпаємо; якщо чіпали - повернути.
