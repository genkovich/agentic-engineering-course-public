# Screencast-сценарії · 10.4 Agent Teams

П'ять скринкастів лекції 10.4 — це **один наскрізний прогін** фічі «звіт по знижках»
у п'яти епізодах. Пісочниця збирається один раз (`make sandbox`), сесія стартує один раз
(епізод 1), далі камера повертається до того самого запуску. Між дублями — `make reset`.

Спільна передумова (ставиться в епізоді 1, решта епізодів — продовження):

```bash
cd ~/sources/agentic-engineering-course/modules/10-agent-teams/10.4-agent-teams
make sandbox          # монореп 10.1 + team-prep коміт: хук і env-флаг УЖЕ на місці
make test             # (опц.) показати: всі пакети зелені, flaky нейтралізовано
make gate-test        # (опц.) обидві гілки хука ізольовано, ще до агентів
cd sandbox
claude                # env-флаг тягне settings.json пісочниці; export не потрібен
```

> Живі агент-сесії недетерміновані: фікстур гарантує стартовий стан (репо + хук +
> зелений сьют), а не однакові кроки агентів. Agent Teams — experimental: записувати
> на pinned-версії Claude Code, перед зйомкою звірити клавіші й флоу з live-доками.

## 🎬 Скринкаст #1 (~1 хв) — спавн команди: прогін стартує

**Слайд:** 3 (спавн команди: file-disjoint план + промпт).

- **Pre-state:** пісочниця з `make sandbox`; `git log --oneline` — видно team-prep коміт
  (хук поставлено ДО спавну); `node --test` зелений; `claude` з кореня `sandbox/`.
- **Тригеримо** (копі-пейст, промпт спавну зі слайда 3 дослівно):
  > Зроби фічу «звіт по знижках» у цьому монорепі. Заспавни трьох тіммейтів:
  > - billing-owner: володіє лише packages/billing/ — додає подію discount.applied при обчисленні знижки;
  > - queue-owner: володіє лише packages/queue/ — доставляє подію до споживачів;
  > - reports-owner: володіє лише packages/reports/ — агрегує події у звіт по знижках.
  > Спершу склади спільний список задач: у кожної задачі свій набір файлів, набори не перетинаються, залежності явні (агрегація залежить від формату події). Формат події тіммейти узгоджують напряму через SendMessage, а не вгадують. Кожен ганяє node --test у своєму пакеті перед закриттям задачі і комітить лише файли свого пакета.
- **Дивимось:** підтвердження спавну; у панелі з'являються три owner-и зі своїми сесіями;
  лід складає спільний список задач із явними залежностями.
- **Кадр-висновок:** жодного «створи команду» — опис фічі природною мовою і твоє
  підтвердження. Команда зібралась, прогін пішов.

## 🎬 Скринкаст #2 (~1 хв) — список задач: конвеєр і файли

**Слайди:** 4 (конвеєр) і 5 (JSON-файли на диску).

- **Pre-state:** прогін триває; список задач фічі складений, залежності явні.
- **Тригеримо:** `Ctrl+T` — панель задач; спостерігаємо кілька хвилин; докидаємо текстом:
  > додай задачу: опиши формат події для README
  У **другому терміналі**:
  ```bash
  ls -a ~/.claude/tasks/<ім'я-команди>/     # .highwatermark  .lock  1.json  2.json ...
  cat ~/.claude/tasks/<ім'я-команди>/3.json # задача агрегації: status + blockedBy
  ```
- **Дивимось:** задача агрегації стоїть заблокована; billing-owner фіксує формат — вона
  розблоковується сама; вільний тіммейт тут же її забирає; докинута задача з'являється
  у списку; у JSON видно `status` і `blockedBy`, поруч лежить `.lock`.
- **Tip для кадру авто-розблокування:** попроси ліда НЕ призначати задачу агрегації нікому
  при спавні. Явно призначену задачу тіммейт може вести й закрити ще до розблокування
  (у живому прогоні #3 закрилась раніше за #1) — `blockedBy` стримує самозахоплення,
  а не роботу над призначеним.
- **Кадр-висновок:** координація лежить у структурі списку, а не в листуванні. І ця
  структура — звичайні файли: можеш подивитись на неї очима.

## 🎬 Скринкаст #3 (~1 хв) — peer-контракт через SendMessage

**Слайд:** 6 (пошта замість ефіру).

- **Pre-state:** прогін триває; reports-owner дійшов до скелета агрегації.
- **Тригеримо:** зазвичай нічого — spawn-промпт вимагає узгодити формат напряму.
  Якщо тіммейти зволікають, підкажи лідові:
  > хай reports-owner спитає формат події у billing-owner-а через SendMessage
- **Дивимось:** у транскрипті reports-owner-а — виклик `SendMessage` до billing-owner-а
  з питанням про поле суми; відповідь приходить назад без участі ліда; у вікні ліда —
  щонайбільше рядок нотифікації, а не цілий діалог (навести `/context`).
- **Кадр-висновок:** контракт події узгоджено одним peer-повідомленням. У субагентній
  моделі цей діалог їхав би два повних кола через ліда.

## 🎬 Скринкаст #4 (~1 хв) — TaskCompleted тримає планку

**Слайд:** 7 (три gate-точки команди).

- **Pre-state:** прогін триває; хук з епізоду 1 на місці. Для гарантованого дубля на
  записі зламай один тест у пакеті тіммейта, який саме доробляє задачу, — у другому
  терміналі:
  ```bash
  # macOS sed; ламає перший strictEqual у тесті billing
  sed -i '' 's/assert.strictEqual(inv.subtotal, 25)/assert.strictEqual(inv.subtotal, 26)/' \
    packages/billing/__tests__/invoice.test.js
  # відновлення після кадру:
  git checkout -- packages/billing/__tests__/invoice.test.js
  ```
- **Тригеримо:** чекаємо, поки тіммейт спробує закрити задачу; за потреби підштовхни ліда:
  > попроси billing-owner-а закрити поточну задачу
- **Дивимось:** тіммейт пробує закрити задачу; хук повертає exit 2; задача лишається
  in progress; у транскрипті тіммейта — фідбек «Тести червоні...»; тіммейт лагодить тест
  і закриває задачу з другої спроби. Паралельно у другому терміналі:
  `cat .claude/logs/team-events.jsonl` — payload TaskCompleted із `task_id` і `task_subject`.
- **Кадр-висновок:** планка якості тримається сама. Хук завертає недороблене без твоєї
  участі — і так на кожній задачі прогону.

## 🎬 Скринкаст #5 (~1 хв) — фінал прогону і shutdown

**Слайд:** 8 (життєвий цикл: сесія vs список задач).

- **Pre-state:** прогін на фініші; задачі фічі закриті або закриваються.
- **Тригеримо** (копі-пейст):
  > Прожени node --test по всіх пакетах, зведи підсумок фічі і розпусти команду.
- **Дивимось:** тести зелені по трьох пакетах; лід зводить підсумок; shutdown-запити
  тіммейтам — кожен погоджується і виходить; після виходу з сесії каталогу команди в
  `~/.claude/teams/` уже немає, а каталог задач у `~/.claude/tasks/` лишився
  (на живій машині в `teams/` можуть лежати каталоги інших сесій — дивись саме на свій).
- **Кадр-висновок:** три шари побудовано паралельно, без жодного конфлікту по файлах.
  Команда пішла, список задач лишився.

## Мапа скринкастів

| Епізод | Слайд | Механізм | Що доводить |
|---|---|---|---|
| #1 спавн команди | 3 | spawn природною мовою, file-disjoint план | команда збирається без «create a team» |
| #2 список задач | 4-5 | shared task list, блокування, self-claim | координація = структура; на диску — JSON |
| #3 peer-контракт | 6 | `SendMessage`, mailbox | пряме листування повз вікно ліда |
| #4 хук-гейт | 7 | `TaskCompleted` + exit 2 | планку тримає хук, не людина |
| #5 фінал | 8 | shutdown consent, життєвий цикл | команда одноразова, список задач — ні |

## Recording runbook

1. **Версія.** Agent Teams — experimental і міняється по кілька білдів на тиждень.
   Записуй на pinned-версії (розроблено і прогнано на v2.1.201); перед зйомкою звір
   клавіші, дефолти й обмеження з live-доками.
2. **Env-флаг.** `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1` уже стоїть в env-блоці
   `sandbox/.claude/settings.json` — окремий `export` не потрібен, але й не зашкодить.
3. **Trust-діалог.** На першому старті `claude` у пісочниці прийми «Yes, I trust this
   folder» — без цього Claude Code мовчки ігнорує `permissions.allow` із settings.json
   (хуки й env-блок працюють і без trust), і агенти впиратимуться в permission-промпти.
4. **Тільки інтерактивно.** Headless `claude -p` команду НЕ спавнить: запит на тіммейта
   деградує в одноразового субагента, каталоги в `~/.claude/teams|tasks` не з'являються
   (жива перевірка 2026-07-05, v2.1.201).
5. **Хук ДО спавну.** `make sandbox` кладе task-gate.sh у `.claude/` пісочниці ще до
   старту сесії — саме так, як каже епізод 1 лекції («закладка на майбутнє»).
6. **Другий термінал.** Тримай відкритим для доказів на диску:
   `ls -a ~/.claude/tasks/<team>/`, `cat <task>.json`, `cat .claude/logs/team-events.jsonl`,
   а після виходу з сесії — `ls ~/.claude/teams/`.
7. **Ctrl+T** — панель задач у сесії (лише перегляд, до п'яти задач).
8. **Епізод 4** має гарантований дубль через `sed`-команду вище; відновлюй файл через
   `git checkout --`, щоб `git status` пісочниці лишався чистим.
9. **Split panes** (опційно): `claude --teammate-mode auto` у tmux або iTerm2 — кожен
   тіммейт у своїй панелі. У VS Code / звичайному терміналі лишайся на in-process.
10. **Permission mode.** Для кадру «підтвердження спавну» (епізод 1) бери дефолтний режим:
    в `acceptEdits` спавн проходить без питання (перевірено живим прогоном). Далі можна
    `acceptEdits`, щоб правки не промптились. `bypassPermissions` НЕ бери: він мовчки
    вимикає хуки — і весь епізод 4 зникає.
11. **Між дублями** — `make reset`: чистий стартовий стан, включно з хуком і зеленим сьютом.
