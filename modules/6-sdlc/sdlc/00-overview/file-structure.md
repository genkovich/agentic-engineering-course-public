# File structure

Two angles: where artefacts land per feature (`docs/features/<slug>/`), and where the templates that produce them live inside the toolkit (`sdlc/`).

## Per-feature artefact layout

```
docs/
  architecture-map.md         # repo-root; written once by map-architecture, read by all skills
  roadmap.md                  # Now/Next/Later/Shipped tables; updated by roadmap + ship-feature
  features/
    <feature-slug>/
      idea-brief.md
      PRD.md
      sad.md                  # SAD (Arc42 12 sections) — C4 L1 inline §3, L2 inline §5
                              # frontmatter: target_surfaces (gates downstream skills)
      diagrams/
        seq-<flow>.md
        deployment.md
        c4-component.md       # L3, optional, out of scope for SAD
      data-model.md
      migrations/             # STAGED — generated by generate-data-model
                              # PROMOTED into live migrations tree by implement-tasks
        <timestamp>_<name>.sql
      contracts/
        openapi.yaml
        events.md
        cli.md
        public-api.md
        api-sync-report.md
      adr/
        0001-<decision>.md
        0002-<decision>.md
      tasks/
        _epic.md
        tracker.md
        <task-slug>.md
        tasks.json            # machine-readable DAG (id, title, layer, deps, acs, dod, files_hint)
      CONTEXT.md              # glossary; fix-term writes here
      test-plan.md
      _review/
        review-<date>.md      # PASS / CHANGES REQUESTED verdict from review-feature 🚪
CHANGELOG.md                  # repo-root; updated by ship-feature
.claude/
  sdlc.local.md               # per-project overrides for implement-tasks (auto-created, gitignored)
```

## Where the templates that produce these artefacts live

```
sdlc/
  plugin/
    agents/
      <agent-name>.md         # 9 agents: explorer/researcher/strategist/analyst/
                              #   devils-advocate/critic/test-author/implementer/reviewer
    skills/
      <skill-name>/
        SKILL.md              # protocol + DoD + anti-patterns
        templates/            # the starter shape THIS skill copies into docs/features/<slug>/
        references/           # mini-guides the skill reads at specific steps
      _shared/                # cross-cutting mechanisms (10 files):
        agent-roster.md       # model/effort policy per agent
        ask-style.md
        critic.md
        diagram-presentation.md
        handoff.md            # stage-handoff block every skill ends with
        interview-depth.md    # depth-dial for ideation
        mermaid-check.md
        size-matrix.md        # XS/S/M/L/XL classification matrix
        socratic-loop.md
        surfaces.md           # target_surfaces taxonomy
  document-templates/         # cross-feature / manual / legacy — pulled by hand
    CHANGELOG.md
    CONTEXT-MAP.md
    migration-plan.md
    task-breakdown.md         # legacy alias
    SPEC.md / arc42.md / architecture-brief.md   # legacy
    adr/NNNN-title.md         # legacy fallback
    diagrams/c4-component.md
```

## Why like this

- **Everything lives in repo** (next to code) — not in Confluence/Notion. Access through git, versioning, code review.
- **`docs/features/<slug>/`** — all per-feature artefacts in one place, not scattered across `docs/`, `wiki/`, `architecture/`.
- **`docs/architecture-map.md`** — single codebase survey written once by `map-architecture`; all stages read it. Prevents repeated codebase scanning and keeps architecture context consistent.
- **`adr/` per feature** — decisions with feature context. Cross-cutting ADRs — under root `docs/adr/`.
- **`migrations/` staged** — `generate-data-model` writes here; `implement-tasks` promotes to the live migrations tree with re-stamped timestamps.
- **`tasks/tasks.json`** — machine DAG that closes the previously-broken implement loop. `implement-tasks` reads it directly.
- **`_review/`** — clean-context review verdict lives here; `ship-feature` reads it as a hard gate.
- **Templates colocated with their owner skill** — each `plugin/skills/<name>/templates/` is the single source for the artefact that skill produces.
- **`plugin/agents/`** — 9 named agents (haiku/sonnet/opus per task type). Model policy in `_shared/agent-roster.md`.
- **`plugin/skills/_shared/`** — 10 cross-cutting files shared by all skills (surfaces, handoff, critic, depth-dial, etc.).

## Slugs

- `kebab-case`, short, no date: `rate-limiting`, `user-import`, `audit-log-v2`.
- NOT `JIRA-1234-rate-limiting` — JIRA ID lives in frontmatter / commits.

## Cleanup

After merge + ship-feature:
- Keep `docs/features/<slug>/` in repo as an archive (read-only).
- Do NOT delete — needed for git blame and majority-decision archaeology.
- After 1 year you can move it to `docs/features/_archive/<year>/<slug>/`.
