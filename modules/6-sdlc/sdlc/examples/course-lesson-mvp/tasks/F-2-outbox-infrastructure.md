# F-2 · Outbox infrastructure (migration `000023` + `internal/outbox/` pkg)

**Epic:** [[_epic|course-lesson-mvp]]
**Priority:** Must
**Estimate:** 1d
**Wave:** 1 (foundation)

## Місце в послідовності

- **Блокується:** нічим. Це нова foundation infra — нема outbox у репо взагалі (verified: `grep -i outbox beer-lms-api/migrations/` → 0 hits).
- **Блокує:** C-5 (`POST /courses/{id}/publish`), L-6 (`POST /lessons/{id}/publish`) — обидва вимагають `INSERT outbox` у тій самій tx що UPDATE.
- **Чому в цій хвилі:** publish-flow — це core engagement loop. Без outbox дві publish-story не можуть закінчити DoD.

## Why (user story)

As a backend developer, I want a transactional outbox primitive (DDL + Go pkg із `Writer` interface), so that publish handlers (course + lesson) можуть атомарно INSERT-ити domain event у тій самій transaction що UPDATE, і downstream consumer (notification, search-index) eventually спожиє event без duplicate-ів від retry-ів.

PRD: AC-06 (course publish idempotent). SAD §6 (publishCourse + publishLesson sequences показують `BEGIN; UPDATE; INSERT outbox; COMMIT`).

## API contract

_No HTTP surface. Internal Go pkg consumed by publish handlers._

```
internal/outbox/writer.go (interface)
  type Writer interface {
    Append(ctx, tx pgx.Tx, evt Event) error  -- INSERT всередині caller-овської tx
  }

internal/outbox/event.go
  type Event struct {
    ID            uuid.UUID  -- UUID v7 generated by Append if zero
    AggregateType string
    AggregateID   uuid.UUID
    EventType     string
    Payload       []byte     -- JSON
  }

internal/outbox/postgres_writer.go (impl)
  func (w *PostgresWriter) Append(ctx, tx, evt) error {
    INSERT INTO outbox_events (id, aggregate_type, aggregate_id, event_type, payload, created_at)
      VALUES ($1, $2, $3, $4, $5, now())
  }

internal/outbox/dispatcher_stub.go
  // Stub — polls pending events і logs. Real consumer side — out of scope v1.
  // Just enough to verify dispatcher contract (table → log line) для integration test smoke.
```

- [ ] **AC-out-2 (migration down):** Given DB after up, when down runs, then table + обидва індекси видалені; повторний up — clean.
- [ ] **AC-out-3 (Append всередині tx):** Given open `pgx.Tx`, when `Append(tx, evt)` called and tx commit-ить, then row з'являється у `outbox_events` із `dispatched_at IS NULL`.
- [ ] **AC-out-4 (Append rollback discards event):** Given tx rolled back, when Append виконано до rollback, then row НЕ з'являється у `outbox_events` (атомарність із caller-овської tx).
- [ ] **AC-out-5 (auto UUID v7):** Given `evt.ID == uuid.Nil`, when Append called, then row.id — валідний UUID v7 (час-впорядкований).
- [ ] **AC-out-6 (dispatcher stub):** Given 3 pending rows у `outbox_events`, when stub dispatcher runs one cycle, then всі 3 logged + `dispatched_at` set; повторний run — 0 нових.

## Edge cases

| Кейс | Поведінка |
|---|---|
| Каller передає `tx == nil` | Append повертає `ErrTxRequired` (нова sentinel у `outbox/errors.go`). Outbox писати без tx — не безпечно (no atomicity guarantee). |
| `evt.Payload` = nil | Append повертає `ErrEmptyPayload`. JSONB NOT NULL не дозволить запис, але робимо early-fail у Go. |
| Concurrent Append із однаковим `evt.ID` | PK UNIQUE — друга tx отримає `pq.unique_violation`. Caller має retry із новим UUID або це bug-сигнал. |
| Dispatcher падає посеред batch | Уже UPDATE-нуті rows mark-нуті dispatched. Що не встигли — лишаються pending; наступний cycle підбере. At-least-once delivery, NOT exactly-once (consumer-side dedup — окрема історія v2). |
