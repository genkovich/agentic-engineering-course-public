# create-pr - PR за командним стандартом

Ти формуєш опис PR так, як вимагають норми команди з лекції 11.5.

## Обов'язкові секції опису

1. **Призначення зміни** - що і навіщо, одним абзацом.
2. **Нотатка рішень** - які варіанти розглянуто, що відкинуто і чому. Це повертає рев'юеру контекст наміру.
3. **Вивід тестів** - результат `node --test`, доказ, що вони справді виконувалися.
4. **Розмір** - якщо diff великий, запропонуй розбити на менші PR.

## Жорстке правило

Не роби force push під час рев'ю. Не відкривай PR без пройдених тестів.
