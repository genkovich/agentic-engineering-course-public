# CLAUDE.md - payments-service

Знеособлений сервіс «компанії A» для лекції 11.5. Структура повторює бойовий шаблон
CLAUDE.md команди: коротко, з власником, у git.

**Власник файлу:** platform-team. Зміни через PR.

## Призначення

`payments-service` приймає запити на виведення коштів, перевіряє баланс і ставить
транзакцію в чергу на обробку. Це критичний сервіс: помилка тут коштує грошей.

## Стек

- Node.js (без зовнішніх залежностей у демо; тести під `node --test`)
- Черга - через `queue.js` (у демо - in-memory заглушка)

## Архітектура

- `src/payments.js` - публічний API сервісу: `requestWithdrawal(account, amount, idempotencyKey)`
- `src/payments.test.js` - тести бізнес-правил

## Критичні правила

1. **Суми - тільки в мінорних одиницях (копійки), цілим числом.** Ніяких float для грошей.
2. **Кожна мутація балансу вимагає idempotency key.** Повторний запит з тим самим ключем не списує двічі.
3. **Не логуй PII і не логуй повний номер рахунку.** У логах - тільки останні 4 цифри.
4. **Від'ємний або нульовий amount - помилка, не «no-op».**

## Пов'язані сервіси

- `ledger-service` (не в цьому репо) - фінальний запис проведення.
- `notification-service` - надсилає підтвердження користувачу.

## Що НЕ робити

- Не додавай auto-retry на списання без idempotency key.
- Не пиши в лог тіло запиту цілком.
- Не змінюй сигнатуру `requestWithdrawal` без узгодження з ledger-team.
- Не вимикай тести, щоб «швидше пройшов CI».
