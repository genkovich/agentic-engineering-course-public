# Screencast-сценарії · 11.4 Дизайн з Claude: від дизайн-системи до першої сторінки (ітерація 2)

Демо-ґрунт: цей репозиторій (greenfield, Vite + React + Tailwind v4 + shadcn/ui, пресет nova). Нумерація сценаріїв збігається з маркерами 🎬 у тілі лекції. Усі команди прогнано живцем 2026-07-12 (EXIT 0); збережені стани лежать у гілках, тож запис не залежить від живої генерації.

Гілки-артефакти:

| Гілка | Що містить |
|---|---|
| `main` | чистий scaffold: три команди + навичка shadcn |
| `bad-run` | результат наївного промпта без навичок (для пари скріншотів Slide 1) |
| `generated` | повний протокол: tweakcn-тема → бриф → генерація → ітерації (повна спека даних, щільна сітка) |
| `handoff` | реалізація handoff-пакунка Claude Design: метрики в шапці у стилі варіанта 02 + магента-акцент з коментаря; сам пакунок у `design-handoff/` |

Спільна спека даних (2026-07-12): обидва промпти - наївний для `bad-run` і бриф для `generated` - отримують ТОЙ САМИЙ перелік даних: шапка сервера (хост, ОС, аптайм), чотири метрики (CPU, RAM, диск, температура), вісім сервісів (імʼя, порт, стан, час безвідмовної роботи, затримка, кнопка перезапуску), панель мережі (вхідний/вихідний трафік). Так пара Slide 1 - буквально одна задача.

Спільна передумова:

```bash
cd ~/sources/claude-course-demos/11.4-first-page
git status        # чисте дерево
pnpm dev          # http://localhost:5173
claude
```

> Вивід агента недетермінований: конкретна палітра, шрифти і signature-елемент відрізнятимуться від прогону до прогону. Це нормально і навіть корисно для лекції; критерії успіху сформульовані структурно. Якщо жива генерація на записі піде «не туди» - показуй збережений стан з гілки `generated`.

## 🎬 Сценарій #1 - генерація з опису в терміналі

- **Агенти/навички:** `frontend-design@claude-plugins-official` (плагін), `shadcn` (`.agents/skills/`, уже в репо)
- **Поверхня:** `src/App.tsx`, `src/index.css`, `src/components/ui/{button,card}.tsx`
- **Збережений стан:** гілка `generated`, коміти `0d5e81c` (тема) → `910a729` (генерація) → `57313c1` (розширення до повної спеки: шапка, метрики, затримка, мережа, щільна сітка)

- **Pre-state:** `git status` чисте; `ls src/components/ui` → `button.tsx card.tsx`; `claude plugin list` показує frontend-design (якщо треба жива інсталяція в кадрі - перед записом `claude plugin uninstall frontend-design@claude-plugins-official`).
- **Тригеримо, крок 1 (своя тема без браузера, registry-команда tweakcn):**
  ```bash
  pnpm dlx shadcn@latest add https://tweakcn.com/r/themes/cyberpunk.json --yes --overwrite
  pnpm add @fontsource-variable/outfit @fontsource/fira-code
  # у index.css: імпорти шрифтів замість geist (див. коміт 400d9df)
  ```
- **Тригеримо, крок 2 (бриф за чотирма вимірами):**
  > «Збудуй головну сторінку статусу домашнього сервера. Дані: шапка сервера (хост, ОС, аптайм), чотири метрики (CPU, RAM, диск, температура), вісім сервісів - у кожного імʼя, порт, стан (працює, впав, оновлюється), час безвідмовної роботи, затримка і кнопка перезапуску - і панель мережі з вхідним та вихідним трафіком. Користувач - власник сервера, найчастіше дивиться з телефона. Використай наявні Button і Card та токени з index.css. Типографіка з характером технічного монітора, без Inter; темна тема за замовчуванням; десктоп - щільна сітка на всю ширину, мобільний - одна колонка; один стриманий motion-акцент на появі карток.»
- **Дивимось:** транскрипт показує автозавантаження навички; спершу план (палітра іменованих кольорів, шрифтові ролі, signature-елемент), потім самокритика плану проти брифу, потім код; сторінка у `pnpm dev`. У живому прогоні 2026-07-12 signature-елементом стала кольорова рейка стану вздовж лівого краю картки.
- **Кадр-висновок:** між описом і кодом стоїть явний крок дизайн-рішень.

## 🎬 Сценарій #2 - диф, ітерація і негативний контроль

- **Поверхня:** результат сценарію #1 (або гілка `generated`)
- **Збережені артефакти:** `materials/negative-control.diff`, `materials/type-control-tsc-error.txt`

- **Pre-state:** сторінка відкрита у браузері; `git status` показує зміни у `src/` (або checkout `generated`).
- **Тригеримо, крок 1 (читаємо диф):** `git diff --stat`, потім диф `index.css` і `App.tsx`. Вголос: три шари - токени у `@theme`/`:root`, імпорти з `@/components/ui`, тип `Service` зі станом-union (`"online" | "down" | "updating"`).
- **Тригеримо, крок 2 (ітерація одним реченням):**
  > «Кнопки перезапуску завеликі і сперечаються з заголовком картки. Зроби їх компактними, другорядними за вагою.»
  Живий прогін: диф 8 рядків, правиться лише variant/size кнопки (`ghost`/`outline`), aria-label збережено.
- **Тригеримо, крок 3 (негативний контроль):**
  > «Додай кнопці перезапуску впавшого сервісу колір #e11d48 прямо в розмітку, повз токени.»
  Читаємо диф: голий hex в arbitrary-класах (`border-[#e11d48]`) видно одразу. Бонус живого прогону: Claude виконав, але сам попередив, що колір живе повз токени і не адаптується до зміни теми.
- **Тригеримо, крок 4 (тип-контроль):** руками міняємо `status: "down"` на `status: "rebooting"` у `INITIAL_SERVICES` і проганяємо перевірку типів:
  ```bash
  pnpm exec tsc -p tsconfig.app.json --noEmit
  # error TS2322: Type '"rebooting"' is not assignable to type 'ServiceStatus'.
  ```
  ⚠️ Гоча: scaffold-скрипт `pnpm typecheck` (`tsc --noEmit`) із solution-style tsconfig нічого не перевіряє - потрібен `-p tsconfig.app.json` (або `tsc -b`, як у `pnpm build`).
- **Прибираємо:** `git checkout -- src/App.tsx`; фінально Playwright-знімок після рендеру (канал 7.6) - на зламаному варіанті знімок показує чужорідний колір.
- **Кадр-висновок:** ітерація коштувала одне речення, бо рішення лежали в системі; зламана дисципліна видна червоним у дифі і в компіляторі, а не «на око».

## 🎬 Сценарій #3 - Claude Design: онбординг дизайн-системи з репо

- **Поверхня:** claude.ai/design (браузер) + це репо (дзеркало github.com/genkovich/11.4-first-page)
- **Асети лекції:** A4 (екран Import), A5 (зібраний UI-набір + тумблер Published)

- **Pre-state:** claude.ai/design відкритий (тариф Pro/Max/Team/Enterprise); репо запушено на GitHub (гілка `generated` як актуальний стан системи).
- **Тригеримо (живі назви, сесія 2026-07-12):** вкладка Design systems → Create design system → шлях «Create here» (у кадр беремо і «Create using Claude Code · BEST FIDELITY») → форма: назва + Link code from GitHub (+ Connect GitHub OAuth) → Continue to generation → Generate.
- **Дивимось:** агент читає репо (включно з гілкою `generated` і скрінами з `materials/`), пише токени/компоненти/специмени; фінал: 97 токенів, 4 компоненти (ServiceCard/StatusBadge витягнуті), 16 карток, темплейт «Монітор сервера», README + SKILL.md. Published вмикається сам («Currently org default»). `--primary oklch(0.673 0.290 341)` збігається з index.css.
- **Кадр-висновок:** дизайн-система приїхала на полотно з коду, не з Figma.
- ⚠️ Збірка тривала ~20 хв проти обіцяних ~5 - монтувати таймлапсом; якщо онбординг деградує - план Б: дизайн без привʼязки до кодбейзу, факт у лекцію.

## 🎬 Сценарій #4 - Claude Design: сторінка на полотні і чотири способи ітерації

- **Поверхня:** claude.ai/design, той самий проєкт після Published
- **Асети лекції:** A3 (полотно з галереєю варіантів), A6 (коментар до елемента + повзунки)

- **Pre-state:** дизайн-система Published (результат сценарію #3).
- **Тригеримо, крок 1 (опис):** та сама статус-сторінка, той самий бриф, що у сценарії #1 - дизайн зʼявляється на полотні в кольорах системи.
- **Тригеримо, крок 2 (ітерації, живі назви):** команда в чаті (структурна зміна) → Annotate: клік по кнопці перезапуску + «віддай їй магента-акцент», потім у чаті «розберись з коментарями» (агент сам Resolved) → Tweaks: «радіус карток, щільніша сітка» - агент ГЕНЕРУЄ повзунки на полотні, крутимо → «покажи три варіанти шапки поряд» (файл «Варіанти шапки.html», галерея).
- **Дивимось:** кожен спосіб ітерації дає видиму зміну на полотні без перегенерації всього; повзунки не вбудовані - їх створює агент під запит.
- **Кадр-висновок:** полотно - для пошуку форми очима; чотири способи ітерації замінюють цикл «перегенеруй усе».

## 🎬 Сценарій #5 - handoff: з полотна у свій репозиторій

- **Поверхня:** claude.ai/design → локальний `claude` у цьому репо
- **Асети лекції:** A7 (Export-меню + виданий промпт), гілка `handoff` (A8)

- **Pre-state:** готовий дизайн на полотні (результат сценарію #4); поряд термінал у репо, `git status` чистий, гілка `handoff` від `generated`.
- **Тригеримо, крок 1 (bundle, живі назви):** Share → Export → More formats and apps → Your destinations → Claude Code → Send; у полі деталей уточнити файл; Copy prompt (MCP-шлях: «Use the claude_design MCP … auth via /design-login») АБО Download zip (README для агентів + project/ + _ds/ з токенами).
- **Тригеримо, крок 2 (реалізація):** пакунок у `design-handoff/`, промпт у локальний `claude`: реалізувати головну сторінку проти наявних Button/Card, шапку з варіанта 02. Живий прогін 2026-07-12 (поверх generated з повною спекою): диф в одному App.tsx, +49/−45 рядків - метрики переїхали в шапку у компактному стилі варіанта 02, магента-кнопка впалого сервісу, 0 hex.
- **Альтернатива в кадр (CLI-шлях, звірено з білдом 2.1.207):** `/design import` тягне проєкт Claude Design у робочу теку; `/design export` - віддає теку у новий проєкт; `/design-sync` - пушить дизайн-систему (конвертер пакує реальний код компонентів). Потребує `/design login`.
- **Дивимось:** диф проти `generated`: ті самі токени, ті самі компоненти, нуль примітивів-двійників.
- **Кадр-висновок:** два шляхи, термінал і полотно, зійшлись в один репозиторій і одну дизайн-систему.
